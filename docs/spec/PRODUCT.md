# Product specification

## Problem

External AI clients need a safe and consistent way to understand and maintain WordPress content. Core post data alone is insufficient for editorial and SEO work because effective metadata may be inherited, generated by an SEO provider, or enriched by add-ons such as Yoast Premium and Local SEO.

Existing REST endpoints are transport-oriented and expose inconsistent shapes. Direct post-meta access is unstable and can leak implementation details. A reusable agent contract needs semantic operations, strict schemas, WordPress-native authorization, and normalized SEO output.

## Product goal

Provide a standalone WordPress 7 plugin that registers provider-neutral content and SEO abilities. The abilities can be consumed through WordPress REST and projected through the official MCP Adapter to Codex, ChatGPT, Gemini, and compatible clients.

## Primary use cases

1. Search and inventory existing posts, pages, and public custom post types.
2. Read complete content in forms useful for editing and analysis.
3. Read configured and effective SEO metadata, including Schema enriched by Yoast Premium and Local SEO.
4. Retrieve editorial context for blog planning without embedding a model into the plugin.
5. Create and update drafts safely in a later milestone.
6. Update explicitly supported SEO fields in a later milestone.
7. Publish only through a separately authorized and explicitly enabled operation.

## Users

- Site owners connecting an external AI client.
- Editors and SEO specialists working through a dedicated integration user.
- Developers adding an SEO provider or client projection.
- Future embedded WordPress agents using the same abilities.

## Success criteria

- A compatible read-only client can find a post and retrieve content plus normalized SEO in at most two ability calls.
- Missing SEO plugins do not break content retrieval.
- Effective Yoast output matches the public frontend/Yoast REST representation for tested objects.
- Local SEO structured data appears through normalized Schema without exposing private plugin options.
- Every operation is bounded, permission checked, schema validated, and auditable.
- No site-specific assumptions are present in the distributed plugin.
- The same domain contracts work through REST, MCP, and internal PHP execution.

## Non-goals for MVP

- Running an autonomous model inside WordPress.
- Generating blog plans inside the plugin.
- Replacing the official MCP Adapter.
- Supporting arbitrary SQL, PHP, filesystem, plugin, or option manipulation.
- Exposing every post-meta or Yoast option key.
- Supporting every SEO plugin in the first release.
- Publishing content autonomously.
- Providing a full editorial calendar UI.

## Product principles

- Domain first, transport second.
- Read before write.
- Explicit contracts over raw database access.
- Effective output and configured intent are different data.
- Capability boundaries are product features, not implementation details.
- Optional integrations must fail soft and report provenance.
