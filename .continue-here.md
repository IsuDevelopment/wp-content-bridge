## What was implemented

- Dedicated, opt-in media read policy (`wpcb_media_reads_enabled`).
- Dedicated capability: `wpcb_read_media`.
- Abilities:
  - `wp-content-bridge/get-media`
  - `wp-content-bridge/get-media-by-id`
- Exact lookup by attachment ID, same-site original URL, and filename; text search remains available.
- Normalized media output: ID, title, filename, URL, ALT, caption, description, and MIME type.
- Content summaries now return both nullable `featured_image_id` and `featured_image_url`.
- `update-seo` now accepts bounded `keyphrase_synonyms` and
  `related_keyphrases` lists with Yoast Premium 28.x, preserves retained
  scores/positional synonyms, and returns both through SEO schema 1.2.
- ADR 0016 extends `update-seo` with merged advanced robots flags and authorized
  Open Graph/Twitter image attachment IDs. Configured output now uses SEO
  schema 1.3.
- Reference review of the local “Enable Abilities for MCP” plugin:
  `docs/research/ENABLE_ABILITIES_FOR_MCP_COMPARISON.md`.
- Plan 4a `wp-content-bridge/list-block-patterns`, independently gated by
  `wpcb_pattern_reads_enabled`, `wpcb_read_patterns`, and native editor access.
  Metadata is the default; optional complete markup is capped at 2 MiB. The
  adapter reads only the current registry and discards filesystem fields.
- ADR 0015 replaces the unreleased `publish-content` plan with the future
  `wp-content-bridge/transition-content-status`. It will use an explicit
  transition graph; public and scheduled states additionally require
  `wpcb_publish_content`, native `publish_post`, and the publication flag.
- `wp-content-bridge/trash-content` is implemented separately. It requires the
  writes flag, trash flag, per-type read + trash policy, `wpcb_delete_content`,
  native `delete_post`, and a fresh version token. It refuses permanent-delete
  fallback when WordPress trash retention is disabled.

The official Adapter reference profile now covers all 12 implemented abilities
and includes only those registered under the current feature flags. The
miniOrange OAuth endpoint has a separate grant table; its profile still needs
runtime verification and explicit update after Kormas Local is started.
